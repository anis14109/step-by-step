`git-ftp` handles deployment by storing a single log file (`.git-ftp.log`) on your hosting server to track the active commit hash.

---

### Step 1: Install `git-ftp` on Your Machine

Choose the installation command for your operating system:

* **Windows (Git Bash):**
Open Git Bash as administrator and run:
```bash
curl -s https://raw.githubusercontent.com/git-ftp/git-ftp/master/git-ftp > /bin/git-ftp
chmod 755 /bin/git-ftp

```


* **macOS (via Homebrew):**
```bash
brew install git-ftp

```


* **Linux (Ubuntu / Debian):**
```bash
sudo apt-get update
sudo apt-get install git-ftp

```



To verify installation, run:

```bash
git-ftp --version

```

---

### Step 2: Configure Your FTP/SFTP Credentials

Navigate to your local Git project directory in your terminal:

```bash
cd /path/to/your/project

```

Set your host configuration using `git config`. These settings will be saved inside your local `.git/config` file:

```bash
# Set server URL (Include path to the live web folder, e.g., public_html)
git config git-ftp.url "ftp://ftp.yourdomain.com/public_html"

# Set FTP Username
git config git-ftp.user "your_ftp_username"

# Set FTP Password
git config git-ftp.password "your_ftp_password"

```

*Note: For secure connections (SFTP), change `ftp://` to `sftp://` and include port `22` if needed (e.g., `sftp://[ftp.yourdomain.com:22/public_html](https://ftp.yourdomain.com:22/public_html)`).*

---

### Step 3: Prevent Confidential Files from Uploading

Create a `.git-ftp-ignore` file in your project root to exclude files that should not go to production (like local configuration files or `.git` data):

```bash
# Create the ignore file
touch .git-ftp-ignore

```

Add unwanted files/directories to `.git-ftp-ignore`:

```text
.env
.gitignore
.git-ftp-ignore
README.md
/node_modules/

```

---

### Step 4: Initialize `git-ftp` on the Remote Server

Choose **one** of the two options below depending on your server's current state:

#### Option A: If your live server is empty (or has old/outdated files)

This command uploads **all tracked Git files** to the server and creates the `.git-ftp.log` file:

```bash
git ftp init

```

#### Option B: If your live server already matches your local code

If your live server already has the current codebase uploaded and you don't want to re-upload everything:

```bash
git ftp catchup

```

*`catchup` creates the `.git-ftp.log` on the server without uploading files, marking the current commit as active.*

---

### Step 5: Daily Workflow (Deploying New Changes)

After making code edits and committing them locally:

```bash
# 1. Stage and commit changes
git add .
git commit -m "Update homepage layout"

# 2. Upload only modified/added/deleted files
git ftp push

```
