# git-ftp — Installation & Configuration Guide (Windows)

Official install reference: **git-ftp's `INSTALL.md`**
`https://github.com/git-ftp/git-ftp/blob/master/INSTALL.md`

Environment: Windows, Git for Windows / Laragon Git, PowerShell.

---

## Overview

git-ftp uploads to FTP/SFTP servers the Git way — it uploads only the files that
changed since the last upload by storing the last deployed commit's id in a log
file on the server.

---

## QUICK START (copy-paste)

> Assumes git-ftp is already installed (Steps 1-5) and the repo below is set up.
> Replace the password and the folder/file contents with your own.

```powershell
$pass = Read-Host "Enter cPanel password"
cd C:\Users\pc\Desktop\yourdomain

git config git-ftp.password "$pass"                 # set once
git add .                                           # stage site files you put here
git commit -m "initial"
git ftp init                                        # first upload (use one of these only)
# git ftp catchup                                   # ...or just mark current state if files already online
git ftp push                                        # deploy later changes
```

One-liner for an existing project (skips init):

```powershell
cd C:\Users\pc\Desktop\yourdomain; git add .; git commit -am "deploy"; git ftp push
```

## Step 1 — Check the environment

```powershell
git --version
Get-Command git       # find which Git is used (e.g. C:\laragon\bin\git\bin\git.exe)
Get-Command curl.exe  # find which curl is used
```

## Step 2 — Confirm curl has SFTP support

SFTP uploads require a curl built with libssh2. The `Protocols:` line of
`curl --version` must contain `sftp`.

```powershell
& "C:\laragon\bin\laragon\utils\curl.exe" --version
& "C:\laragon\bin\git\mingw64\bin\curl.exe" --version
```

> Git for Windows / Laragon Git ships a curl with SFTP support out of the box,
> so normally no separate curl download is needed. Only if your curl's protocols
> list lacks `sftp` should you install a curl build with SFTP support and remove
> `bin/curl.exe` from Git's installation directory.

## Step 3 — Pick a writable `bin` directory that is in PATH

The `git` command finds `git-ftp` because it is placed in a directory on PATH.
`Program Files\Git` needs admin rights; a user-writable alternative is
`C:\laragon\bin\git\usr\bin` (already on the user PATH).

```powershell
Test-Path "C:\laragon\bin\git\usr\bin"   # True
```

## Step 4 — Install git-ftp (download the script)

```powershell
& "C:\laragon\bin\git\mingw64\bin\curl.exe" -L -sS `
  https://raw.githubusercontent.com/git-ftp/git-ftp/master/git-ftp `
  -o "C:\laragon\bin\git\usr\bin\git-ftp"
```

> This mirrors the official `INSTALL.md` command `curl ... > /bin/git-ftp`,
> adapted to a user-writable directory.
> Windows ignores the `chmod 755` step from the Unix guide.

## Step 5 — Verify the install

```powershell
git ftp --version   # git-ftp version 1.6.0
```

## Step 6 — Create the site repo and configure

git-ftp reads its settings from the git repository of the site you deploy.
The config is stored per-project in that repo's `.git/config`.

```powershell
New-Item -ItemType Directory -Path "C:\Users\pc\Desktop\yourdomain" -Force | Out-Null
cd C:\Users\pc\Desktop\yourdomain
git init -b main

git config git-ftp.url      "sftp://yourdomain.com:22"
git config git-ftp.user     "sirikoti"
git config git-ftp.password "{cpanelPass}"
```

> Notes:
> - git-ftp has **no separate port setting** — the port goes into the URL, e.g.
>   `sftp://host:22`. The port 22 is the default for SFTP.
> - `{cpanelPass}` is a placeholder. Replace it with the real cPanel password:
>   `git config git-ftp.password "your_real_pass"`
> - The credential is stored in plaintext in `.git/config` (repo-local only).

## Step 7 — Verify the config

```powershell
git config --local --list | Select-String "git-ftp"
```

Expected output:

```
git-ftp.url=sftp://yourdomain.com:22
git-ftp.user=sirikoti
git-ftp.password={cpanelPass}
```

## Usage

```powershell
cd C:\Users\pc\Desktop\yourdomain

# put your site files into this folder, then:
git add .
git commit -m "initial"

git ftp init      # first upload to the server
git ftp catchup   # alternative: if files are already on the server, mark current commit without uploading
git ftp push      # every later change, uploads only what changed
```

Troubleshooting: add `-v` or `-vv` for verbose output, e.g. `git ftp push -vv`.

## Deploying to a subfolder

### The remote path lives in the URL

With `git-ftp.url = sftp://host:22`, files land in the SFTP login root. To deploy
into a specific folder (or subfolder) on the server, add the path to the URL:

```powershell
git config git-ftp.url "sftp://yourdomain.com:22/public_html"   # web root
git config git-ftp.url "sftp://yourdomain.com:22/public_html/shop"  # subfolder
```

The whole file tree of your commit goes into that folder, keeping the repo's
relative structure.

### Upload only a subfolder of your repo — `git-ftp.syncroot`

If your committable files live in a subfolder locally (e.g. `dist/`, `build/`,
`public/`) and you only want that subtree uploaded, point git-ftp at it:

```powershell
git config git-ftp.syncroot "dist"
git ftp push   # uploads only files under dist/ into the remote path
```

### Common scenarios

| Goal | Config |
|---|---|
| Upload repo root to server root | `git-ftp.url = sftp://host:22` |
| Upload repo root to web root | `git-ftp.url = sftp://host:22/public_html` |
| Upload a local subfolder only | `git-ftp.syncroot = dist` + any url |
| Two folders on the server | change `git-ftp.url` per repo (or use two repos) |

> git-ftp still tracks the last commit globally, so switching to a different
> subfolder in the same URL requires a fresh `git ftp init` (or `catchup`)
> against that location.
